# ADR 0022: Parameterize slide themes without changing Classic

Date: 2026-10-26
Status: Accepted (Phase 1 implementation; release pending review)

## Context

Preview, fitting, splitting and PPTX export previously read one palette, font and
layout directly. Future lesson-level looks need those paths to agree without
changing teacher content or today's default output. Phase 1 introduces the seam;
it does not introduce selection, new fonts, new looks or a wire-format field.

## Decision

`src/lib/themes/types.ts` defines SlideTheme: id/name, six-digit hex palette tokens
without #, exportFace, previewFont (CSS font-family), metricsId, visual card shape
and layout. The layout preserves the existing numeric/percentage units while
widening literal values for future geometry. Sayuna Classic composes the unchanged
exports in `src/lib/slide-theme.ts` and retains the actual layout object references.
Readability floors and safety margins remain shared policy in that legacy module.

`src/lib/themes/index.ts` owns DEFAULT_THEME_ID (sayuna-classic), the const THEME_IDS
tuple, the registry, DEFAULT_THEME, getTheme and isThemeId. getTheme defaults to
Classic for missing/unknown IDs; isThemeId provides exact validation. Future wire
validation must use the guard rather than accepting the rendering fallback.

fitSlide, getSlideOverflow and suggestSplitIndex accept the theme after
originalWriters; autoFitDeck accepts it second; createPresentationPptx and
buildPresentationPptx accept it third, after images. fitText and titlePointSize
also accept a trailing theme to propagate font/layout choices. Every argument is
optional and defaults to Classic, so existing callers keep their behavior.
SlideView accepts a theme prop; EditableSlideView inherits and forwards it and
uses its geometry for the empty-body editing target. No route, schema or client
request changes in this phase.

SlideView reads palette, shape and browser family from the theme while retaining
the existing local Poppins CSS-variable class. PPTX reads the same palette/layout,
export face and border width. Corner radius is a percentage token. Classic keeps
PowerPoint's native roundRect adjustment omitted, preserving exact XML; other
radii map to inches of the shorter card side, with zero selecting a rectangle.
Additional decoration treatments remain a separate future phase.

`src/lib/slide-fit-metrics-registry.ts` maps metricsId to the existing regular/bold
Poppins metrics. Unknown IDs throw rather than silently measuring another face.
Fitting uses the selected widths and title line height. The generator accepts
font-face arguments (for example Poppins), loading bundled Regular/Bold TTFs;
no arguments retains Poppins and its exact generated bytes. Additional faces
produce separate modules and require explicit registry registration. No new font
files or metric tables ship in Phase 1.

## Contrast policy

`src/lib/themes/contrast.ts` computes WCAG sRGB relative luminance and enumerates
eight foreground/background uses. Titles require 3:1 as large text; part label,
body, heading, muted, counter, credit and placeholder text require 4.5:1.
`tests/lib/themes/contrast.test.ts` compares the complete failing-pair list against
three exact product-approved Classic exceptions:

| Text use | Foreground | Background | Ratio | Required |
|---|---|---|---|---|
| Part label | 06B6D4 | F0F9FF | 2.28:1 | 4.5:1 |
| Slide counter | 94A3B8 | F0F9FF | 2.41:1 | 4.5:1 |
| Visual placeholder text | 0284C7 | E0F2FE | 3.57:1 | 4.5:1 |

These colours remain unchanged by product decision to preserve Classic's
appearance and export bytes. A new failing pair fails the test. An exception
that starts passing also fails the test, requiring removal of the stale entry.
New themes receive no implicit exemptions.

## Provenance and consequences

The separation of palette/typography, shape and later decoration was informed by
[ppt-master](https://github.com/hugohe3/ppt-master), investigated at commit 78759bf.
It is design inspiration only: no engine, scripts, assets or text were adopted.
[ADR 0009](0009-ppt-master-not-adopted.md) remains the engine decision.

Classic's accessibility exceptions and installed-font substitution risks remain.
This plumbing does not prove new-theme rendering or native PowerPoint font fit.
Selection/export wiring belongs to Phase 2; Arimo/Gelasio and new palettes belong
to Phase 3. Phase 1 is verified by unchanged XML snapshots, fixed-date archive
entry comparisons, serialized HTML comparison and stubbed browser captures.
